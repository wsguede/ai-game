## Tech Stack

- **HTML/CSS** — all styles inline in `index.html`; no preprocessors
- **Vite** — build tool only (`npm run dev` for dev, `npm run build` → `docs/`)

## Source Layout

```
src/
  data/          — static config (CANDIES, LOCATIONS, EVENTS, ERA_V1)
  engine/        — game logic (State, Market, Heat, EventEngine, UI, Game)
  main.js        — barrel: imports all source files in dependency order
index.html       — Vite entry point; all HTML + CSS
tests/           — browser-only test harness (open tests/index.html)
docs/            — Vite build output (gitignored — CI deploys to pages branch)
planning/        — design specs, implementation plans, architecture docs
```

## Window Global Pattern

Each source file uses dual assignment so the binding is available both in the
module's own scope and on `window`:

```js
var Heat = window.Heat = (function() { ... })();
```

Cross-file dependencies are captured at the top of each IIFE:

```js
var Game = window.Game = (function() {
  var State = window.State;
  var Heat  = window.Heat;
  // rest of Game — function bodies reference State and Heat directly
})();
```

`eras.js` uses `window.CANDIES`, `window.LOCATIONS` etc. directly (plain object,
not an IIFE).

## Load Order

Enforced by `src/main.js`:

```
candies → locations → events → eras → state → market → heat → event-engine → ui → game
```

## Build & Test Commands

```bash
npm run dev          # Vite dev server with hot reload
npm run build        # builds to docs/ locally (gitignored — do not commit)
npm run preview      # preview built output locally
npm test             # Vitest unit tests (63 tests in src/tests/)
npm run lint         # ESLint on src/
npm run setup-hooks  # install git hooks — run once per fresh clone
```

Push to `main` to trigger CI/CD (tests → lint → build → deploy to GitHub Pages).

## Git Workflow

**GitHub Flow:** all changes on a feature branch, pushed and merged via PR. No
direct commits to `main`. `main` is always deployable.

**Branch naming:** `feat/<name>` · `fix/<name>` · `chore/<name>` · `docs/<name>`

**Conventional Commits** (enforced by `commit-msg` git hook):

```
<type>: <subject ≤72 chars, imperative mood, no trailing period>

- Bullet explaining what changed
- Bullet explaining why / non-obvious decisions

Co-Authored-By: <Agent Name> <email>
```

Allowed types: `feat` · `fix` · `docs` · `chore` · `refactor` · `test`

**PR description template:**

```markdown
## Summary
- [what changed]
- [why / what problem it solves]

## Test Plan
- [ ] npm test — all tests pass
- [ ] npm run lint — no errors
- [ ] Open game in browser (npm run dev) — plays correctly, zero console errors
- [ ] UI changes verified manually in browser
```

## Safe Operations

These commands are routine — any agent may run them without asking for confirmation:

| Category | Commands |
|---|---|
| Explore | `ls`, `find`, `cat` |
| Git read | `git status`, `git log`, `git diff`, `git branch` |
| Test/lint | `npm test`, `npm run lint` |
| Dev server | `npm run dev`, `npm run preview` |
| PR/issue read | `gh pr view`, `gh pr list`, `gh issue view`, `gh issue list` |

**Requires confirmation before running:** `git push`, `git reset`, `git checkout --`,
`gh pr create`, `gh pr merge`, any destructive operation.

## Do Not

- Commit directly to `main`
- Commit the `docs/` directory (gitignored; CI produces and deploys it)
- Add npm runtime dependencies (dev dependencies are fine)
- Use a framework, TypeScript, or CSS preprocessor
- Skip `npm run setup-hooks` on a fresh clone

- [ ] **Step 3: Create the hook script**

```bash
cat > scripts/hooks/commit-msg << 'EOF'
#!/usr/bin/env bash
set -euo pipefail

commit_msg_file="$1"
first_line=$(head -1 "$commit_msg_file")

# Allow merge commits
if echo "$first_line" | grep -qE "^Merge "; then
  exit 0
fi

# Conventional commit pattern: type(optional-scope)?: subject (1-72 chars)
pattern="^(feat|fix|docs|chore|refactor|test)(\(.+\))?: .{1,72}$"

if ! echo "$first_line" | grep -qE "$pattern"; then
  echo "" >&2
  echo "  ERROR: Commit message does not follow Conventional Commits format." >&2
  echo "" >&2
  echo "  Required format:  <type>: <subject>" >&2
  echo "  With scope:       <type>(<scope>): <subject>" >&2
  echo "" >&2
  echo "  Types: feat, fix, docs, chore, refactor, test" >&2
  echo "  Subject: imperative mood, max 72 chars, no trailing period" >&2
  echo "" >&2
  echo "  Example: feat: add smoke bomb consumable item" >&2
  echo "" >&2
  echo "  Your message: $first_line" >&2
  echo "" >&2
  exit 1
fi

exit 0
EOF
chmod +x scripts/hooks/commit-msg
```

cat > scripts/setup-hooks.sh << 'EOF'
#!/usr/bin/env bash
set -euo pipefail

REPO_ROOT="$(git rev-parse --show-toplevel)"
HOOKS_SRC="$REPO_ROOT/scripts/hooks"
HOOKS_DST="$REPO_ROOT/.git/hooks"

for hook in commit-msg pre-push; do
  ln -sf "$HOOKS_SRC/$hook" "$HOOKS_DST/$hook"
  chmod +x "$HOOKS_SRC/$hook"
  echo "  installed: $hook"
done

echo "Git hooks installed. Run 'npm run setup-hooks' after each fresh clone."
EOF

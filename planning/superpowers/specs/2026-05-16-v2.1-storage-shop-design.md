# v2.1 — Storage + Shop Design

## Overview

Introduces the shop system and the first item category: storage upgrades. The shop is always accessible via a persistent button in the action bar. Purchasing an item locks candy trading for the rest of that turn but does not end the turn — the player still ends it manually via END TURN, LAY LOW, or travel.

---

## Shop System Rules

- **Always accessible.** The SHOP button appears in the action bar at all times, including during bully events. Opening the shop has no penalty.
- **Purchase locks candy trading.** Once the player buys anything from the shop, all candy buy/sell actions are disabled for the rest of that turn. The market table shows all rows as greyed out with a "TRADING LOCKED" label.
- **Turn continues normally.** After purchasing, the player can still lay low, travel, or end the turn manually.
- **Warning on first two purchases (lifetime).** The first two times the player clicks BUY in the shop, a confirmation step appears inside the shop modal: *"Heads up: buying from the shop locks candy trading for the rest of today. You'll still need to end the turn yourself."* with CONFIRM / CANCEL. Cancelling does not count — `shopWarningCount` only increments on a confirmed purchase. After two confirmations (`shopWarningCount >= 2`), BUY purchases immediately with no warning.
- **Tiers must be bought in order.** The shop shows only the next available tier. There is no indication of what tiers exist beyond the one currently available.
- **Capacity is replaced, not stacked.** Buying Fanny Pack sets `stashCapacity = 10`. Buying Satchel later sets it to `20`. The new tier's capacity is the total, not an addition.

## Architecture

### New files

**`src/data/shop.js`** — plain config object, no IIFE:
```js
window.SHOP = {
  storage: {
    category: 'storage',
    tiers: [
      { tier: 1, name: 'Fanny Pack',  capacity: 10, price: 20,  flavor: 'Dorky but effective. Nobody suspects the fanny pack.' },
      { tier: 2, name: 'Satchel',     capacity: 20, price: 50,  flavor: 'Messenger bag. Holds a lot. Looks like homework.' },
      { tier: 3, name: 'Backpack',    capacity: 50, price: 120, flavor: 'Standard issue. Fits everything. Raises zero eyebrows.' },
    ]
  }
};
```

**`src/engine/shop.js`** — IIFE module:

- `getNextTier(category)` — returns the next unpurchased tier object for the given category, or `null` if all tiers are owned.
- `canBuy(category)` — returns `true` if the next tier exists and the player has enough cash.
- `purchase(category)` — deducts cash, sets `ownedTiers[category]`, sets `stashCapacity` to the new tier's capacity, sets `shopPurchasedThisTurn = true`, increments `shopWarningCount`. Returns `true` on success, `false` if the player cannot afford it.

### State additions (`src/engine/state.js`)

Added to `_state` in `init()`:

```js
ownedTiers: { storage: 0 },  // tier level owned per category (0 = default)
shopPurchasedThisTurn: false, // blocks candy buy/sell for the rest of this turn
shopWarningCount: 0,          // lifetime purchase confirmations shown
```

`shopPurchasedThisTurn` resets to `false` at the top of `startTurn()` alongside the other per-turn flags. `ownedTiers` and `shopWarningCount` persist for the full run.

### Game.js additions

Three new functions exposed on `Game`:

- **`openShop()`** — populates `#shop-content` with the next storage tier card (or "maxed out" message) and shows `#shop-modal`.
- **`buyTier(category)`** — handles the purchase flow:
  1. If `s.shopWarningCount < 2`: render the warning message and CONFIRM/CANCEL in the shop modal. CONFIRM proceeds to step 2. CANCEL closes the warning.
  2. Call `Shop.purchase(category)`. On failure (can't afford), show an inline error. On success, push a notification (`"Bought Fanny Pack — bag upgraded to 10 slots"`), close the shop modal, re-render.
- **`closeShop()`** — hides `#shop-modal`.

**Candy trading guard:** At the top of `executeBuy` and `executeSell`:
```js
if (s.shopPurchasedThisTurn) return;
```

### UI.js changes

**`renderMarket`** — receives `shopPurchasedThisTurn` as a new parameter. When `true`, all rows get `row-disabled` class and no `onclick`. The `🎒 IN BAG` column header gains a `TRADING LOCKED` label in muted red.

**`renderActions`** — always appends the SHOP button after the existing context-sensitive buttons, regardless of game state:
```js
html += '<button class="action-btn" onclick="Game.openShop()">🛒 SHOP</button>';
```

### HTML additions (`index.html`)

New shop modal alongside the existing trade modal:

```html
<div id="shop-modal" class="modal-overlay" role="dialog" aria-modal="true" aria-label="Shop">
  <div class="modal">
    <h3>🛒 SHOP</h3>
    <div id="shop-content"></div>
    <div id="shop-warning" class="modal-error"></div>
    <div class="modal-actions">
      <button class="action-btn" id="shop-confirm" style="display:none">CONFIRM</button>
      <button class="action-btn" id="shop-cancel" onclick="Game.closeShop()">CLOSE</button>
    </div>
  </div>
</div>
```

## Testing

Existing Vitest tests (`npm test`) cover State, Market, Heat, EventEngine — none touch shop logic. New unit tests added to `src/tests/shop.test.js`:

- `getNextTier` returns correct tier when none owned, mid-progression, and fully maxed
- `canBuy` returns `false` when maxed or insufficient cash
- `purchase` sets `ownedTiers`, `stashCapacity`, `shopPurchasedThisTurn`, deducts cash correctly
- `purchase` returns `false` and leaves state unchanged when player can't afford

UI and game-flow behavior (warning count, trading lock, SHOP button in action bar) verified manually in the browser.
